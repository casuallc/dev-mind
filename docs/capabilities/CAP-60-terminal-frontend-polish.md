# CAP-60 远程终端前端打磨（字体 / 字号调节 / ANSI 颜色渲染）

> 能力 ID：CAP-60 ｜ 分类：前端体验 ｜ 状态：**需求定稿** ｜ 日期：2026-09-23
> 依赖 CAP-58/59（远程终端）。纯前端增强，零后端/协议改动，安全模型不涉。
> 对应「Xshell 化」方向 A（方向 B 持久 shell/补全/取消已由 CAP-59 落地）。

## 1. 目的

CAP-59 把终端能力补齐（持久 shell / Tab 补全 / 取消），但渲染仍是「裸文本」：
`ls --color`、git、claude 等工具输出的 ANSI 转义序列原样糊在屏幕上（`[32m` 乱码），
字体是系统默认 Consolas 12px 不可调。本能力做三件纯前端的事：

1. **ANSI 颜色渲染**：SGR 颜色/粗体/下划线等渲染为真实样式，控制序列一律吞掉；
2. **等宽字体栈升级**：优先 JetBrains Mono / Cascadia Code 等编程字体（本机没装自动回落）；
3. **字号调节**：工具栏 A−/A+ 按钮，10–20px，localStorage 持久化。

## 2. 功能需求

### FR-01 ANSI 转义序列渲染（`shared/chat/workspace/ansi`）

- 自写解析器（不引依赖）：输入裸文本，输出分段（segment）序列，前端按段渲染
  `<span>`。支持：
  - SGR 基础：reset/bold/dim/italic/underline、16 色前景（30-37/90-97）、
    16 色背景（40-47/100-107）；
  - 256 色与 truecolor：`38;5;n`/`48;5;n`（xterm 立方体+灰阶换算）、`38;2;r;g;b`；
  - 其余序列一律吞掉不显示：非 SGR 的 CSI（光标移动/清屏等）、OSC（标题/超链接）、
    字符集切换、`\r`（进度条回车按「覆盖到行尾」简化为丢弃——终端面板是追加式
    日志模型，不支持原地重绘，记录在案）。
- 无样式的段继承父级颜色（stdout 浅灰 / stderr 红的现有口径不变，带色段覆盖）。
- 解析器为纯函数（无 React 依赖，可 node 直跑冒烟）；渲染层薄封装成 ReactNode。

### FR-02 字体栈

- 终端主体/输入框/候选弹层统一：
  `'JetBrains Mono', 'Cascadia Code', 'Cascadia Mono', Consolas, Menlo, 'Courier New', monospace`。
  不打 webfont（离线/内网环境，本机没装自动回落 Consolas）。

### FR-03 字号调节

- 终端面板顶部工具栏：A− / 当前字号 / A+（10–20px，步进 1，默认 12）。
- localStorage `devmind.terminal.fontSize` 持久化，跨会话/跨页面生效。
- 输入框与候选弹层字号跟随。

## 3. 关键设计

- **为什么自写 ANSI 解析器**： ansi-to-react 等库要么只支持 16 色要么带一串
  依赖；追加式面板只需要 SGR 一个子集，百行内可覆盖且可单测。
- **不支持原地重绘**：`\r`/光标移动按丢弃处理——`tail -f` 类追加输出无影响，
  进度条/动态刷新类（npm 进度条）只保留最终行内容的一部分，可接受（交互式
  重绘属方向 C PTY 范畴）。

## 4. 验收标准

1. `printf '\033[32mGREEN\033[0m \033[1;31mBOLDRED\033[0m\n'` 渲染绿色/粗红而非乱码；
2. 256 色（`\033[38;5;208m`）与 truecolor（`\033[38;2;255;100;0m`）上色正确；
3. 带光标控制序列的输出（如 `\033[K` 清行）不出现 `[K` 残留字符；
4. 无 ANSI 的 stdout/stderr 渲染与现状逐像素一致（回归）；
5. A−/A+ 调字号即时生效，刷新页面保持；
6. `npx tsc -b` 通过；解析器 node 冒烟脚本通过。
