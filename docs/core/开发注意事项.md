# 开发注意事项（单点踩坑记录）

> 收录标准：只在特定任务域才会碰到的坑。任意任务都适用的红线在根目录 CLAUDE.md。

## Windows / 本机 E2E 环境

- **起后端**：`mvn -pl devmind-app -am spring-boot:run` 会失败（root 聚合器报 "Unable to find a suitable main class"）。先 `mvn -q install -DskipTests`，再 `mvn -pl devmind-app spring-boot:run`（不带 -am）。CAP-34 起服务端零执行（无 `--devmind.session.executor` 开关）——会话/问答必须由 runner 执行。
- **起 runner（本地开发）**：配置 `tmp/runner/agent.properties`（gitignored；scripts/dev.ps1/dev.sh 首次运行自动生成模板）——填 `token`（起后端后 后台 → Agent 节点 新建节点如 `local-dev` 复制 token，建议设平台默认），`executor=claude|fake`。启动：`java -jar devmind-agent-runner/target/devmind-agent-runner.jar tmp/runner/agent.properties`（自测无 claude 环境用 `executor=fake`）。**runner jar 重新构建后必须重启 runner 进程**（运行中 jar 被 mvn 覆盖会新旧类混装，表现为 409 ack 超时）。
- **停后端**：IDE/任务工具停掉 mvn 后，spring-boot:run fork 出的 app JVM 不死 → 下次起不来或跑旧代码。必须 `netstat -ano | grep :8080 | grep LISTEN` 拿到 PID 后 `taskkill //PID <pid> //F`。**停 runner**：无监听端口，按命令行特征杀——`powershell -NoProfile -Command "Get-CimInstance Win32_Process -Filter \"Name='java.exe'\" | ? { \$_.CommandLine -match 'devmind-agent-runner' } | % { Stop-Process -Id \$_.ProcessId -Force }"`。
- **runner 服务化部署**：分发包 runner 可注册系统服务（Linux systemd `bin/dev-mind-agent install`；Windows WinSW `bin/dev-mind-agent.ps1 install`），详见 [../guides/runner-service-deploy.md](../guides/runner-service-deploy.md)。
- **中文乱码假象**：Python `json.load(sys.stdin)` 在 Windows 按 GBK 解码 curl 的 UTF-8 输出 → 中文全花，不是服务端 bug。用 `json.load(sys.stdin.buffer)`；curl 中文请求体用 `--data-binary @file`（UTF-8 文件）+ `charset=UTF-8` 头。Windows python 读不了 Git Bash 的 /tmp 路径，一律走 stdin 管道。surefire 控制台输出的中文日志在 Git Bash 下同样会花，属显示问题。
- **资源过滤占位符风格**：父 pom 是 spring-boot-starter-parent，maven-resources-plugin 的过滤分隔符被改为 `@...@`（`${}` 留给 Spring 占位符）——被 filtering 的资源（如 runner 的 runner-version.txt）里写 `${project.version}` 不会替换，必须写 `@project.version@`。
- **健康检查**是 `/api/health`（README 正确；scripts/dev.ps1 旧版探测 `/health` 已在 CAP-34 一轮修正）。
- **application-local.yml 不进 jar/dist**：devmind-app 的 maven-jar-plugin 已排除 `application-local*`，本机专属配置只进 target/classes 供 spring-boot:run；dist 侧覆盖写外置 `config/application-local.yml`（bin/dev-mind 经 additional-location 加载，优先于 jar 内配置）。此前它随 jar 进 dist 包，任何 dist 实例裸起直连打包机的共享库（2026-09-08 E2E 误写共享 MySQL 即此因）。
- **H2 文件库** `jdbc:h2:file:./data/devmind;AUTO_SERVER=TRUE`，相对 app 工作目录。清数据优先走 API 删除；`data/` 整个删掉可全新重来（auth.key/server-crypto.key 会自动重新生成）。
- **系统 JDK**：构建要求 21。若 mvn 报 "不支持发行版本 21"，是 JAVA_HOME 指到了 17——先 `export JAVA_HOME="$(cygpath -w ~/.jdks/temurin-21.0.11)"` 再跑 mvn（以本机实际 JDK 21 路径为准）。

## PostgreSQL

- **@Lob 列类型约定（三库通吃）**：`@Lob` 必带 `@JdbcTypeCode`——String 用 `SqlTypes.LONGVARCHAR`、byte[] 用 `SqlTypes.LONGVARBINARY`，配 `@Column(length = 16_777_216)`。PG 建列为 text/bytea、MySQL 为 longtext/longblob、H2 亦正常；读写走 getString/setString、getBytes/setBytes，不经大对象 API。**裸 @Lob（CLOB/BLOB）在 PG 落成 oid 大对象**，两类故障：auto-commit 路径读抛 "Large Objects may not be used in auto-commit mode"（派生查询不在事务内时触发，findById 反而正常，时好时坏）；对 LOB 字段 lower()/cast 渲染成 bytea 报 "function lower(bytea) does not exist"。回归网：`devmind-common` 的 `LobColumnTypeTest`。
- **存量 oid 库迁移**：`ddl-auto=update` 不转换已有列类型。从旧版升级的 PG 库须先手工跑迁移 SQL（生成在 `tmp/alter_pg_oid_to_text.sql`，gitignored）：`ALTER TABLE t ALTER COLUMN c TYPE text USING convert_from(lo_get(c),'UTF8')`（bytea 用 `lo_get(c)`），单事务、数据无损；顺序=先跑 SQL 再启动新包。转换后 pg_largeobject 残留孤儿大对象，`vacuumlo` 清理或忽略。
- **PG 需提前手工建库**：MySQL 的 `createDatabaseIfNotExist=true` 在 PG 无对应机制，`createdb devmind` 或等价操作先行。

## H2 / JPA

- **ddl-auto=update 只增不删**：改名/删除的列与旧表（如已作废的 tasks 表、task_id 列）会残留在 dev 库。验证前如需干净schema，手动 DROP 或删 `data/` 换全新库。
- **H2 保留字**不能作列名：`commit`→`commit_sha`、`version`→`release_version`。新增列名先对照 H2 关键字表。
- **派生查询 `projectId = null` 匹配不到行**（SQL 空比较）：scope=project 且未传 projectId 的列表必须走不带 projectId 条件的独立查询方法（见 KnowledgeEntry 列表）。
- **EntityManager 整体替换式更新**（PUT 全量替换子集合）必须 @Transactional，否则删除报 "No EntityManager"（CAP-10 a939212 修过）。
- 异步方法内读刚 save 的行：靠 save 自身事务即时提交，**不要**给外层触发方法加 @Transactional（见 CLAUDE.md 红线）。

## Jackson 3（Spring Boot 4）

- `ObjectNode` 迭代用 `properties()`，不是 `fields()`。
- `Map.of(...)` 不允许 null 值——组装响应只放非空字段。
- HTTP 下载/读取文本必须 `byte[]` + UTF-8 解码：对端返回 `text/plain` 无 charset 时 StringHttpMessageConverter 按 ISO-8859-1 解码 → 中文乱码。
- 时间全局格式在 `devmind-app` 的 `JacksonConfig`（yyyy-MM-dd HH:mm:ss，REST 与 WS 同一 ObjectMapper）。新增 Instant 字段无需任何注解，勿加 @JsonFormat 散点定制。

## 执行器 / SSH 测试

- 本地步骤由 LocalStepRunner 走 **Git Bash**（`devmind.execution.shell=bash`），`sleep`/`echo` 可用；Windows 专属命令不可用。
- 远程执行只能跑**命令模板白名单**（script_templates 表），未登记模板（如 noop）按预期失败，不是 bug。
- 嵌入式测试 SSH server（MINA SSHD :2222）**不转发 stderr**——`>&2` 不会进 ExecResult.stderr。失败摘要取值顺序：stderr 首行 → stdout 末行 → exit 码。
- MINA SSHD 加载 ed25519 私钥（BEGIN OPENSSH PRIVATE KEY）需要 `net.i2p.crypto:eddsa` 依赖（devmind-server-adapter 已含，勿删）。

## API 杂项

- **multipart 表单字段（非文件 part）中文乱码**：客户端不带 charset 时 Tomcat 按 ISO-8859-1 解码表单字段。已在 `application.yml` 配 `server.servlet.encoding.charset: UTF-8 + force: true` 全局修正；curl 验证时注意 Git Bash 调原生 curl.exe 会把 argv 中文转成 GBK 字节——multipart 中文值用 `-F "field=<utf8文件"` 喂，别内联。
- 通知 WS/JSON 字段名是 `eventType`（不是 type）。
- 分页接口在数据少时可能直接返回数组而非 `{items}` 包装——写脚本两种形态都要兜。
- 服务器/构建步骤等资源的增删走 project 作用域端点：`/api/projects/{id}/servers/{sid}`；`/api/servers/{id}` 没有 DELETE。
- 通知动作处理器等跨模块 SPI 必须用 `ObjectProvider<T>` 注入，否则启动期循环依赖（handler→SessionManagerService→NotificationService→handlers）。
